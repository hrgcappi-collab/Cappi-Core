# Cappi Core

Смена цен в Syrve через API и контроль того, что цена доехала до витрин —
сайта `cappi.ua` и Glovo.

## Зачем

Раньше переоценка была ручной: зайти в Syrve HQ через RDP, создать приказ об
изменении прейскуранта, дождаться обмена, нажать «Выгрузить», синхронизировать
в админке, проверить сайт. Полчаса кликов на одну цену.

Теперь приказ создаётся одной командой в телеграме, а бот сам проверяет
результат через 30 минут.

## Как устроена цена в Cappi

Цена живёт в Syrve, сайт — только витрина. Правка цены в админке сайта
переживёт ровно до следующей синхронизации, после чего Syrve перезапишет её
обратно.

```
Приказ об изменении прейскуранта  (Syrve ТП, через API)
   └─ Выгрузка меню  (автоматически, раз в 20 минут)
        └─ Синхронизация  →  cappi.ua
        └─ отдельным каналом  →  Glovo
```

Важно: **`defaultSalePrice` в карточке товара — не прейскурант.** Это «цена по
умолчанию», она устаревает и часто расходится с реальной. Настоящую цену брать
из `/resto/api/v2/price` или из Cloud API.

## Файлы

| Файл | Что делает |
|---|---|
| `bot.py` | телеграм-бот: смена цен и проверка витрин |
| `cappi.py` | общая библиотека — Syrve Server API, Cloud API, парсеры сайта и Glovo |
| `check_prices.py` | разовая сверка Syrve ↔ сайт ↔ Glovo из терминала |
| `price.py` | быстрый просмотр цены из Cloud API |

## Установка

```bash
cp api.env.example ~/.cappi/api.env
chmod 600 ~/.cappi/api.env
# заполнить доступы
python3 bot.py
```

Зависимостей нет — только стандартная библиотека Python 3.

## Команды бота

```
/price окрошка          найти позицию и её цену
/set 03275 46           сменить цену (с подтверждением кнопкой)
/set 03275 46 завтра    приказ на завтра
/check                  сверка Syrve ↔ сайт ↔ Glovo
/pending                что стоит на проверке
```

После смены цены бот через 30 минут сам проверит сайт и Glovo и напишет,
доехало ли.

## Безопасность

- доступ только по списку `TELEGRAM_ALLOWED_IDS`; пустой список — запрет всем
- приказ проводится только после подтверждения кнопкой
- скачок цены больше 50% блокируется — защита от опечатки вида `460` вместо `46`
- все изменения пишутся в `~/.cappi/changes.log`
- очередь проверок переживает перезапуск бота

## Что через API нельзя

- **Выгрузку меню не запустить.** Её нет в Server API ни на одном сервере,
  и поддержка Syrve подтвердила, что разрабатывать не планируют — процесс
  переносят на веб-меню. Полагаемся на автовыгрузку раз в 20 минут.
- **Новое блюдо на сайт не завести.** Если позиции нет в выгрузке, её id
  через API не получить и в выгрузку не добавить. Добавление остаётся ручным.

## Ловушки Syrve

- **Приказы живут на ТП-базе** `cappi.syrve.online`, не на HQ. На HQ эндпоинт
  есть, но отдаёт пусто.
- **Эндпоинт называется `menuChange`**, не `menuChangeOrder`.
- **Номера приказов повторяются по годам** — искать по дате, не по номеру.
- **Подразделений два** — проверять, в каком у позиции есть цена.
- **Авторизация занимает слот лицензии** — всегда `logout` после работы.
