# Передача проекта · что где лежит и как поднять с нуля

Этот файл написан для одного случая: открыть новый чат с ассистентом и
за несколько минут вернуть его в курс дела, не пересказывая три недели
работы. Он описывает, **что существует**, **где лежат ключи** и **как
это развернуть**. Значений ключей здесь нет и быть не должно — они живут
в двух местах, и оба указаны ниже.

Состояние на 26.09.2026.

---

## 1. Первое сообщение для нового чата

Скопировать целиком:

> Проект Cappi — сеть доставки в Одессе, два филиала. У меня три бота и
> аналитика поверх Syrve. Прочитай в репозитории `~/code/Cappi-Core`
> файлы `CLAUDE.md` (память проекта, там все ловушки с датами),
> `ПЕРЕДАЧА.md` (что где лежит), `ЭЛАСТИЧНОСТЬ.md` (замер спроса) и
> `аудиты/финальный/AUDIT_REPORT.md`. Доступ на сервер — `ssh cappi-bot`.
> Ключи — в `~/.cappi/api.env` локально и в `data/api.env` на сервере.
> После этого скажи, что понял, и жди задачи.

Больше ничего пересказывать не нужно: всё, за что было заплачено
сломанными ценами и потерянным временем, записано в `CLAUDE.md`.

## 3. Доступы: где лежат и что умеют

**Значения ключей в этом файле не хранятся.** Они в двух местах:

    локально   ~/.cappi/api.env                     chmod 600
    на сервере ~/app/cappi-core/data/api.env        chmod 600

Файл `api.env.example` в репозитории перечисляет все имена переменных с
комментариями — по нему поднимается новая установка.

### Что за чем стоит

| Ключ | Что открывает | Осторожно |
|---|---|---|
| `SYRVE_SERVER_URL` + `SYRVE_API_LOGIN` / `PASSWORD` | Сервер сети (HQ): номенклатура, техкарты | Техкарты пишет только HQ, не ТП |
| `SYRVE_TP_URL` + `SYRVE_TP_LOGIN` / `PASSWORD` | Торговая точка: **приказы о ценах**, OLAP, явки, остатки | Умеет менять цены. Сессий не больше трёх — лицензия |
| `SYRVE_DEPARTMENT` | Подразделение «Cappi Одесса» | Без него приказ уезжает в Днепр. Проверено больно |
| `SYRVE_CLOUD_URL` + `SYRVE_CLOUD_API_KEY` + `SYRVE_ORG_ID` | Cloud API: заказы, статусы, стоп-листы, меню доставки | Слотов лицензии не занимает |
| `TELEGRAM_BOT_TOKEN` + `TELEGRAM_ALLOWED_IDS` | Джарвис | Один поллер на токен, иначе делят сообщения |
| `LOOPA_URL` + `LOOPA_TOKEN` | Отзывы и жалобы | Ключей у Loopa несколько, нужен «на показатели» |
| `CAPPI_ADMIN_URL` + `CAPPI_ADMIN_TOKEN` | Админка api.cappi.ua | Токен пустой — Core туда не ходит |
| `JAMSHUT_URL` + `JAMSHUT_TOKEN` | Опрос зон у Джамшута | Только чтение |
| `JAMSHUT_SAY_TOKEN` | Написать в чат администраторов через Джамшута | Только цифры, не голос от первого лица |
| `CORE_WEBHOOK_TOKEN` + `CORE_WEBHOOK_PORT` | Приём событий зон, 127.0.0.1:8787 | Наружу не смотрит |
| `OPENAI_API_KEY` | Языковая модель: разбор фраз, голос, агент | Core — gpt-5.6-terra, Джамшут — luna |

У Джамшута свой `.env` в `~/app/deliverybot/.env` — там ещё
`OPENWEATHER_API_KEY`, `LOOPA_MANAGE_KEY`, три токена своего API с
разными правами и настройки болтовни.

### Что нужно сменить (не сделано)

Пароли и ключи, которые пересылались в переписке, считаются
скомпрометированными: пароль Syrve (оба логина), токен телеграм-бота,
ключи Loopa, Cloud и OpenAI. Порядок: выпустить новые → положить в оба
`api.env` → перезапустить контейнеры. Это единственный оставшийся
Critical из финального аудита.

## 4. Как поднять с нуля

### Локально (макбук)

```bash
git clone git@github.com:hrgcappi-collab/Cappi-Core.git ~/code/Cappi-Core
cd ~/code/Cappi-Core
mkdir -p ~/.cappi && cp api.env.example ~/.cappi/api.env
chmod 600 ~/.cappi/api.env        # заполнить значениями
python3 selftest.py               # должен сказать «все экраны отвечают»
```

Зависимостей нет — только стандартная библиотека Python 3.12. Для
выгрузок в Excel нужен `openpyxl`, для Word — `python-docx`; оба ставятся
`python3 -m pip install`.

### На сервер

```bash
./deploy/выкатить.sh
```

Скрипт сам прогоняет `tests/приказ.py`, `tests/права.py`,
`tests/непонятые.py` и `selftest.py`, отказывается выкатывать при красном
тесте и при запущенном локальном боте, потом rsync и `docker compose up`.

`data/` не переносится — она живёт только на сервере.

### Проверить, что живо

```bash
ssh cappi-bot 'docker ps; docker logs cappi-core --tail 5'
```

В боте: «⚡ Сейчас», «🩺 Здоровье», «🔌 Проверка связи».

### Откатить

```bash
git checkout <прошлый коммит> && ./deploy/выкатить.sh
```

Меньше двух минут. Состояние в `data/` откату не подлежит — оно
совместимо между версиями.

## 6. Что было сделано в этой сессии

### Бот

- Языковая модель на запасном пути: скрипт → выученное → модель → сразу
  в выученное. Голос через расшифровку. Учёт расходов по двум ботам.
- Агент: ходит в Syrve несколько раз подряд, четыре инструмента,
  необратимое — только через карточку подтверждения.
- Кнопка «🐞 Ошибка» с лентой разговора за три дня.
- Два формата отчёта — оперативный и итоги дня, по форме заказчика.
- Недельный отчёт по понедельникам, KPI администраторов отдельным экраном.
- Сторож источников: раз в сутки проверяет девять интеграций, сообщает
  только о переменах.
- Сторож витрины сайта: спрашивает «точно так и надо?», а не решает сам.
- Атомарная запись состояния, ночной бэкап, ловля второго экземпляра.

### Аналитика

- `ЭЛАСТИЧНОСТЬ.md` — замер спроса на девяти месяцах: постоянная цена
  −0,3…−1,0, акция −2,8, порог безубыточности −1,40. Скрипты в
  `аналитика/эластичность/`.
- `ПРАЙС-ПРЕДЛОЖЕНИЕ.md` — разбор двух прошлых повышений.
- `аналитика/клієнти.py` — база клиентов по блокам среднего чека.
- `аудиты/финальный/` — финальный предрелизный аудит: отчёт, findings,
  план исправлений, чек-лист выката. Волны 1–3 закрыты, кроме смены ключей.

### Документы для людей (в `выгрузка/`, в git не попадают)

    Маркетинговий план · жовтень 2026.xlsx      6 листов, включая базу рассылок
    Маркетингові плани акцій · жовтень 2026.docx  4 плана по образцу заказчика

## 7. Открытые хвосты

1. **Сменить скомпрометированные ключи** — единственный Critical.
2. **`шеф_id` не задан** — запрос правок часов 2-го числа некому слать.
   Ставится `/people шеф_id <id>`.
3. **Решение по ценам не принято**: мягкий вариант (витрина 0 /
   середина +5 / хвост +10) или средний (3/8/12). Расчёты в
   `ЭЛАСТИЧНОСТЬ.md`.
4. **Сверка наборов** (26.09): три набора дороже суммы частей, у двух
   фудкост выше 31%, «Вершкова креветка» с постоянной скидкой 40% ломает
   три набора сразу. Корректировка предложена, приказ не создан.
5. **Веб-интерфейс** — макет опубликован, живой сервер не сделан.
6. **Сторож «филиал молчит»** — предложен после сбоя кассы Лазаревой
   18.09, не реализован.

## 8. Правила, которые нельзя нарушать

Полный список с датами и ценой каждой ошибки — в `CLAUDE.md`. Самое
короткое изложение:

- Приказ о цене **создаётся, а не редактируется**; списком — одним
  приказом; ставится на завтра, срабатывает ночью.
- **Днепр не наш нигде** — только `SYRVE_DEPARTMENT`.
- **Деньги считаются по ПиУ**, не по продажам OLAP.
- `UniqOrderId` без фильтра по еде задваивает.
- Голос одного бота не отправлять ртом другого.
- Секреты только в `api.env`, в git не попадают.
- Перед коммитом — `selftest.py` и `tests/непонятые.py`.
- Чужого на сервере не трогать.
