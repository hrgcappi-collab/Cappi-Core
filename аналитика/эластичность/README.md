# Как пересчитать эластичность

Выводы — в `ЭЛАСТИЧНОСТЬ.md` в корне репозитория. Здесь только то, чем
они посчитаны.

Данные тянутся из Syrve заново и в репозиторий не кладутся: это продажи
по блюдам за девять месяцев, им место не в гите.

    python3 тяга.py /tmp/эластичность      # выгрузка из Syrve, ~2 минуты
    python3 панель2.py /tmp/эластичность   # дневные цены → недельная панель
    python3 события.py /tmp/эластичность   # все смены цены
    python3 событие.py /tmp/эластичность   # событийная эластичность + плацебо

Дальше в любом порядке, все берут ту же папку первым аргументом:

    оценка4.py     панель с эффектами блюда и недели
    горизонт.py    отклик на разных сроках
    срезы.py       дорогие против дешёвых, ходовые против редких
    крупные.py     двадцать позиций с повышением на 8% и больше
    ревизии.py     массовые ревизии 27.07 и 24.08 по отдельности
    акции.py       эпизоды снижения цены по дням
    каннибал.py    что в это время происходит с группой
    кампании.py    акции пачками, в деньгах
    мощность.py    какой шаг нужен, чтобы замер вообще состоялся
    сценарии3.py   ярусы меню и деньги
    итог.py        сводка

`мнк.py` — общий: МНК с двусторонними эффектами и кластерной ошибкой.
Без внешних библиотек, как и весь проект.

Три ловушки, на которых это ломалось:

- **Цена из чеков, а не из приказов.** Сумма без скидки на штуки — это
  то, что видел гость. Приказы говорят, что задумано, чеки — что вышло.
- **Цену недели брать по дням, а не по штукам.** Средняя, взвешенная
  штуками, падает сильнее в те дни, когда продаж больше, — и сама
  рисует отрицательную связь, которой нет.
- **День без продаж — это ноль, а не пропуск.** Пока ожидание считалось
  только по дням с продажами, оно было завышено, и любая акция выглядела
  разорительной: −15 тыс ₴ в день на ровном месте.
